> **状态** · 已完成

## 1. 概述

机器学习基础，指的是理解**模型是如何从数据里学出来的**，以及这个学习过程决定了它能做什么、不能做什么、以及什么时候该往哪个方向改。

它的价值不在于会推导算法，而在于提供一套**在输出不确定的系统上做判断的心法**。面对"准确率 83%，下一步该做什么"，机器学习基础给你的不是某个技术，而是一个诊断顺序：是先补数据、是先换模型、还是先把误差拆开看看错在哪。没有这套心法，改进就只能靠碰运气。

不掌握它，最典型的后果是**把力气花在错误的维度上**：数据量远远不够却去调模型结构、训练集表现很好却上线拉胯、或者面对 83% 的准确率完全不知道下一步该动什么。更深一层的问题是，你可能根本不知道存在哪些取舍——比如准确率、训练速度、推理速度、数据需求之间是互相牵制的，只优化其中一个往往在牺牲另一个。

## 2. 图谱中的定位

这是 Part 1 六个子技能中的最后一个。吴恩达对它的定位有两层，第一层是"几乎所有事都建在这上面"：

> "Modern LLMs are built using machine learning techniques including supervised learning and reinforcement learning. Every engineer I know that's good at building with LLMs also understands machine learning and deep learning at some depth."
>
> 现代大语言模型是建立在机器学习技术之上的，包括监督学习与强化学习。我认识的每一个擅长用大模型做构建的工程师，都以某种深度理解机器学习与深度学习。

第二层是"很多应用仍然需要机器学习本身"——不论是用别人训好的模型，还是自己训一个。他列出的具体要求包括：

- 知道主流的机器学习与深度学习模型，以及它们在**准确率、训练速度、推理速度**等方面的取舍
- 理解如何**工程化地准备训练与评估所需的数据**
- 掌握 **bias/variance（偏差/方差）、误差分析、数据工程**这三个概念——他把它们称为"在不确定输出的系统上工作时，用来做各类决策的核心心法"

## 3. 核心概念

### 3.1 三大范式

| 范式 | 学什么 | 数据形式 | 典型用途 |
|---|---|---|---|
| **监督学习** | 从「输入 → 标注答案」的配对中学习映射 | 有标注 | 分类、回归、检测、评分 |
| **无监督 / 自监督** | 从数据自身结构中学习表征 | 无标注 | 预训练、嵌入、聚类、异常检测 |
| **强化学习** | 通过与环境交互、依据奖励信号调整策略 | 奖励信号 | 决策与序列行动；也用于把人类偏好对齐进模型 |

值得注意的一点：**现代大模型的训练是多阶段混合的**——先在海量文本上做自监督预训练，再用带标注的示范做监督微调，最后用基于人类偏好的强化学习来对齐输出。理解这条流水线，才能理解为什么同一个基础模型在不同对齐阶段表现差异巨大。

### 3.2 一次训练的标准流程

| 阶段 | 作用 | 关键纪律 |
|---|---|---|
| **训练集** | 用来拟合参数 | 不拿它评估性能 |
| **验证集（dev set）** | 用来做决策——选模型、调参、判断方向 | 反复用它，所以它也"会过拟合" |
| **测试集** | 只在最后用一次，估计真实表现 | 用多了就失去意义 |

**一个容易被忽略的纪律**：验证集的分布必须反映**你要部署的真实场景**，而不是你手头数据的分布。如果训练数据来自一个来源、真实用户来自另一个来源，那验证集就该按真实用户来抽。吴恩达在《Machine Learning Yearning》里把这条讲得很重：验证集和测试集要来自**同一个分布**，且这个分布应该是你真正关心的那个。

### 3.3 偏差与方差：两种失败模式

这是最实用的诊断框架。把训练误差和验证误差放在一起看，就能定位问题类型：

| 情况 | 诊断 | 主要对策 |
|---|---|---|
| 训练误差高，验证误差也高 | **高偏差（欠拟合）** | 更大的模型、更丰富的特征、训练更久 |
| 训练误差低，验证误差远高于它 | **高方差（过拟合）** | 更多数据、正则化、简化模型 |
| 两者都高，且验证误差比训练误差高很多 | **高偏差 + 高方差** | 两件事都要做 |
| 两者都低 | 不错 | 可以试试更大的模型看还有多少空间 |

**先诊断再动手**是这套框架的全部意义。它把"效果不好"这个模糊感受，变成了一个具体的问题类型，从而指向具体的动作。

### 3.4 可避免偏差与人类水平表现

偏差本身不能直接告诉你"还有多少空间"。吴恩达提出的做法是**找一个参照点**：人类水平表现（或某个已有系统的表现）。

逻辑是这样的：如果人类能做到 1% 错误率，而你的模型是 10%，那么**可避免偏差约 9 个百分点**——这告诉你还有大量机会，值得继续投入。反过来，如果人类是 7.5%、你是 8%，可避免偏差只有 0.5 个百分点，那么继续压偏差的回报很小，注意力应该转向**方差和数据分布**。

这个思路在今天依然有效：把"当前最好的模型"或"专家表现"作为参照，比空想一个目标数字有用得多。

### 3.5 学习曲线：该加数据还是该加模型

学习曲线是"训练集规模 vs 误差"的曲线，用来回答一个具体问题：**增加数据还有用吗？**

| 曲线形状 | 判断 |
|---|---|
| 验证误差随数据增加仍明显下降 | 加数据有用 |
| 验证误差已经平了，而训练误差在上升 | 数据不是瓶颈，模型容量或特征才是 |
| 两条曲线之间始终有一大段间隙 | 方差问题，加数据是最直接的出路 |

### 3.6 训练与测试分布不匹配

一个独立于偏差/方差的失败来源：**训练数据的分布和真实场景的分布不一致。**

典型表现是：训练误差和验证误差都很低，但上线后表现明显差。这不是过拟合，也不是欠拟合——模型在它见过的分布上学得很好，而线上是另一个分布。

处理方法通常是：从真实分布里抽一小批数据作为专门的验证集（"训练-验证集"），用它来定位不匹配；再把真实分布的数据逐步补进训练集。**诊断用的数据必须和部署场景同分布**，这是处理这类问题的前提。

### 3.7 误差分析：手动看错例

这是全篇最高杠杆的动作。做法非常朴素：

1. 从验证集里取出**模型答错的样本**。
2. **逐个看，用手工的方式分类**——为每一类建一列，用表格统计每类有多少个。
3. 统计完一批（实践中约 100 个错例就足够建立直觉），得到各类错误**按频次排序**的分布。
4. 优先处理**占比最大**的那一类。

**为什么值得手动做**：因为它会反复推翻你的直觉。人们通常高估自己刚想到的那类问题的重要性。做完一次误差分析之后，"下一步该做什么"往往变得非常明确，而且和之前设想的不同。

这个方法和 1.4 里讲的 eval 方法论是同一条脉络——**先看数据，再决定测什么**。区别在于 1.4 面向 LLM 应用的 trace，这里面向传统模型的错例，但顺序和纪律完全一致。

### 3.8 模型选择的取舍矩阵

| 维度 | 要问的问题 |
|---|---|
| 准确率 | 这个任务需要多高？和人类水平差多少？ |
| 训练成本 | 训练一次要多久、花多少？会重训几次？ |
| 推理成本 | 每次调用多少钱、多少延迟？调用量多大？ |
| 数据需求 | 需要多少标注数据？标注贵不贵？ |
| 可解释性 | 出错时能不能定位原因？有没有合规要求？ |
| 部署约束 | 能不能自托管？有没有延迟硬指标？ |

**没有"最好的模型"，只有"在这个约束下合适的模型"。** 大模型在准确率上占优，但推理成本、延迟、部署难度都更高——这些都属于取舍。

### 3.9 数据工程：被低估的一半

吴恩达近年反复强调的一个转向：**从模型为中心转向数据为中心。** 意思是，当模型选择大体上已经收敛（大家都用少数几个强模型），进一步提升效果的空间更多在数据质量上，而不是在模型结构上。

需要工程化的部分包括：标注的一致性（不同标注者对同一规则的理解是否统一）、数据的覆盖度（哪些切片样本太少）、标签噪声（标注本身有多少错误）、以及数据版本管理。**在真实项目里，标注噪声常常是精度上限，而不是模型容量。**

## 4. 深入原理

### 4.1 经典的偏差-方差 U 型曲线不是全部：双下降

教科书说：模型越复杂，先变好后变坏，呈 U 型。这个图在现代深度学习里**是不完整的**。

> Belkin, Hsu, Ma & Mandal, *Reconciling modern machine learning practice and the bias-variance trade-off*, PNAS, [arXiv:1812.11118](https://arxiv.org/abs/1812.11118)

该论文指出：现代实践中，参数量远超样本数的模型被训练到**几乎完全拟合训练数据**（插值），按经典理论这应当严重过拟合，但它们在实际测试数据上表现很好。

把模型容量作为横轴，真实的曲线是这样的：

| 区间 | 行为 |
|---|---|
| 容量 < 样本数 | 经典的 U 型下降段——经典的图只描述这一段 |
| 容量 ≈ 样本数（插值阈值） | **风险达到峰值**——模型勉强能插值，方差极大 |
| 容量 ≫ 样本数 | **风险再次下降**——这就是「第二次下降」（double descent） |

这解释了为什么"更大的模型反而更好"在深度学习中反复成立：**它超出了经典理论覆盖的范围。** 对工程的含义是——不要把教科书上的 U 型曲线当作选模型容量的依据；在实践中，容量往往不是主要的风险来源。

### 4.2 容量不等于泛化：网络能记住随机标签

一个更激进的实验结论：

> Zhang, Bengio, Hardt, Recht & Vinyals, *Understanding deep learning requires rethinking generalization*, ICLR 2017 — [arXiv:1611.03530](https://arxiv.org/abs/1611.03530)

实验设计很干净：拿一个在 CIFAR-10 上达到 94% 测试准确率的网络，**把真实标签替换成完全随机的标签**，然后照常训练。结果：

- 训练准确率仍然达到 **100%**——网络把任意一种标注都记住了。
- **损失曲线看起来几乎没有区别**——从训练过程本身看不出标签是随机的。
- 显式正则化（如 dropout、权重衰减）**并不能阻止**这件事。
- 换成完全无结构的随机噪声图片，现象依旧。

含义非常尖锐：**模型容量本身无法解释它为什么泛化。** 同一套架构既能记住随机标签，也能在真实标签下泛化到 94%——两者的区别不在模型，在数据。任何基于容量的理论界（VC 维、Rademacher 复杂度）对这类网络都是**空洞的**（界限数值大于 1，什么都说明不了）。

对实践的含义：**"模型太大所以过拟合"是一个不可靠的推断。** 如果模型能记住随机标签却在真实数据上失败，问题很可能在**数据质量、标注或分布**上，而不是容量上。

### 4.3 「更多数据」也有反直觉的一面

双下降现象还有一层：它不仅出现在模型容量维度，也出现在**训练样本数**维度。

> Nakkiran et al., *Deep Double Descent: Where Bigger Models and More Data Hurt*, [arXiv:1912.02292](https://arxiv.org/abs/1912.02292)

论文标题本身就是结论——**在特定区间内，增加模型规模或增加数据量都可能让效果变差。** 这是与直觉相悖的，但机制与 4.1 相同：当模型和数据量处在「插值阈值」附近时，系统处于最不稳定的状态。

实践含义：**小数据集上的模型对比结论往往不可靠。** 在数据量不足时，A 比 B 好这个结论可能只是因为两者都落在阈值附近，换了数据量结论就翻转。做模型选型时应当意识到这一点，尽量在接近真实数据规模下比较。

### 4.4 误差分析的具体纪律

把 3.7 展开成可执行的流程，有几条纪律值得单列：

| 纪律 | 原因 |
|---|---|
| **只看错例，不看对的** | 对的样本不提供改进信息 |
| **一次只看一个主要问题** | 一个样本可能有多处问题，但归类时取最主要的那个，否则统计无法收敛 |
| **先分类，不先归因** | 一上来就想"为什么错"会陷入无底洞，而且会带偏你注意到什么 |
| **用表格统计频次** | 目的是排序，不是记录 |
| **样本量要够（约 100 个）** | 太少会碰到的是偶发问题，不是主要问题 |

**最高频的那一类，往往不是你最先想到的那一类。** 这就是手动做误差分析的全部理由。

### 4.5 数据为中心：为什么把精力放到数据上

在模型选择已经收敛的场景里（今天大致如此），提升空间的分布已经变了：

| 动作 | 典型收益 |
|---|---|
| 换一个更强的模型 | 边际收益递减，且成本上升 |
| **清理标签噪声** | 可能直接抬高精度上限 |
| **补充缺失切片的数据** | 通常能修复某类系统性失败 |
| **统一标注规则** | 减少训练信号里的自相矛盾 |

吴恩达把这套思路称为从"模型为中心"到"数据为中心"的转向，其核心主张是：**当模型已经足够强，决定系统表现的是数据的质量与覆盖，而不是模型的选择。**

需要强调一个前提：**你无法通过模型修好一个标注错误的样本。** 如果标注本身是错的，任何模型都会被教错——而且它会在验证集上也表现为"错误"，让你误判模型能力。

### 4.6 人类水平表现为什么是好基准

用人类表现作参照点，好处有三个：

1. **它是一个可测量的量**，不像"理想表现"那样是空想。
2. **它把偏差拆成"可避免"和"不可避免"两部分**，直接告诉你还有多少空间可拿。
3. **它随任务难度自动缩放**——语音识别的人类水平很高（因为人类容易疲劳），图像分类的人类水平也很高（因为人类也会看错，如把哈士奇认成狼）。所有任务的贝叶斯最优误差都接近"完美"，但人类水平离它有多远，因任务而异。

需要留意的是：**在人类表现已经不如模型的领域（如某些大规模知识问答），这个基准就失去了参照价值**，此时应改用其他参照（如更强的既有系统）。

### 4.7 LLM 时代这些框架为什么仍然适用

一个自然的疑问是：大模型时代，还需要这些传统框架吗？答案是需要，而且更贴切：

- **偏差/方差**变成了"提示与上下文够不够"（偏差）与"对单个样本过度拟合、换个措辞就失败"（方差）的两个方向。
- **误差分析**变成了 1.4 里讲的 error analysis 循环——读 trace、开放式编码、按频次排序。两者是完全同构的。
- **数据为中心**变成了"检索进来的材料质量"。
- **分布不匹配**变成了"评测集和真实用户分布不一致"。

**根本原因没有变**：只要系统的输出不确定，你就只能靠测量来推进，而测量的核心问题是"看什么、怎么看、看完之后改什么"。机器学习基础提供的正是这套判断的词汇。

## 5. 能力检查点

1. 我能说明监督、无监督、强化学习三者的区别，并描述现代大模型的多阶段训练流水线。
2. 我能解释训练集、验证集、测试集各自的角色，以及为什么验证集的分布必须反映真实部署场景。
3. 我能根据训练误差与验证误差的组合，判断问题属于高偏差、高方差还是两者兼有，并给出对应动作。
4. 我能解释可避免偏差的含义，并说明如何用人类水平表现来量化它。
5. 我能用学习曲线的形状判断"增加数据是否还有用"。
6. 我能解释训练-测试分布不匹配与过拟合、欠拟合的区别，以及如何诊断它。
7. 我能按纪律手动完成一次误差分析，并说明为什么必须按频次排序而不是按直觉排序。
8. 我能解释"双下降"现象，并说明为什么教科书上的 U 型曲线不足以作为选模型容量的依据。
9. 我能说明"网络能拟合随机标签"这一实验结果的含义，以及它对"模型太大导致过拟合"这一推断的影响。
10. 我能说明数据中心主义的转向及其前提，并解释为什么标注错误无法靠模型修好。
